# Native desktop milestone

```sh
cargo run -p pdf-editor-offline-native
```

Eframe/egui 0.36.2 provides a native accessible widget tree and window; rfd provides native file dialogs. The app runs without a web server, webview or remote renderer. PDFs are parsed with `pdf-core` and rasterized with `pdf-render` on one background worker. A one-slot command channel and one active UI request prevent render-request accumulation. Page, zoom, document and revision keys discard stale results.

Open up to 16 PDF tabs, navigate pages, zoom, change dark/light theme, rotate the current page, undo/redo, and Save As. The workstation has a resizable Pages/Search/Text sidebar, a document/page inspector, a centered page canvas, real action menus, a command palette and bottom status/navigation. The inspector collapses below a 960-point window width; extracted text remains available in the sidebar. Original paths are never overwritten. Save uses the core's validated, no-clobber atomic write. Signed and encrypted inputs are read only. Password entry, signing, OCR, redaction, forms, arbitrary text editing and conversion are not implemented by this milestone. A successful preview does not establish PDF fidelity; unsupported content may be omitted by Hayro.

Search extracts actual text one page at a time on the worker and matches a literal query, with optional case sensitivity. Case-insensitive matching uses Unicode lowercase equivalence. Results select the matching page and show an excerpt with compact whitespace; the Text sidebar retains the original extracted text. Search does not provide page-coordinate highlights. Searches stop at 200 matching pages, queries allow 256 characters, and page text is capped at a UTF-8 boundary within 1 MiB. The UI reports partial search/text limits. A read-only selectable page-text control exposes the extracted text through the widget accessibility tree; actual platform screen-reader behavior remains unverified. Search generation, document and revision keys discard stale results. New page renders take priority over subsequent search pages.

The native UI embeds unmodified IBM Plex Sans Regular and Medium for offline body, button and heading typography. The warm ivory light theme and forest/ink dark theme share a restrained copper accent, consistent spacing and readable focus/selection states. Font source pins, payload hashes and the required license are in [IBM Plex provenance](assets/fonts/ibm-plex/PROVENANCE.md). An unmodified 1.2 MiB Noto Sans Symbols 2 font remains the final fallback; it supplies symbols such as `✓` in extracted text. Its pinned source, SHA-256 and OFL notice are in [Noto provenance](assets/fonts/PROVENANCE.md). Native distributions must include **both** `assets/fonts/OFL.txt` and `assets/fonts/ibm-plex/OFL.txt`. These fonts do not guarantee coverage of every Unicode script.

The compact forest header groups working menus/actions. Active document tabs retain accessible selection state, sidebars have deliberate spacing, the page sits on a calm ivory/ink canvas, and the inspector keeps long file paths in a tooltip instead of occupying the reading area. The inspector scrolls vertically in short windows. Narrow windows use File-menu Open/Save actions when the direct buttons do not fit. Light is the initial theme; View or the command palette switches to dark. Theme tests check consistent widget/type colors and at least 4.5:1 contrast for critical text pairs; that is not a complete accessibility audit.

Closing a modified tab or quitting with unsaved changes prompts before discarding. Save failures keep the edits and document open. Main preview caches retain at most 64 MiB of RGBA pixels across tabs, evicting other tabs when necessary; this counts pixel payloads, not driver allocations or transient copies. Up to eight history snapshots are retained, within an additional 256 MiB budget measured by serialized bytes. That is an estimate of clone memory, not a hard process-memory limit. Input/output limits and an in-process thread do not contain malicious parser/decompression failures; a resource-limited subprocess remains required for hostile-file isolation.

Page rasterization uses logical document zoom × the window's physical pixels-per-point ratio. A Retina display therefore renders two pixels per logical point at 100% zoom, while the canvas divides the raster size by that ratio. Device ratio, logical zoom and actual raster scale are part of each request key; monitor/DPI changes invalidate stale cached or pending images. The visible CropBox/MediaBox intersection and page rotation determine a safe raster plan. Output remains limited to 8192 pixels per side and 16,777,216 pixels total. If the requested physical resolution would exceed those bounds, the raster resolution is reduced while desired logical page size and zoom remain unchanged, and the canvas reports the resolution limit.

Keyboard: Command/Ctrl+O opens, Command/Ctrl+S saves a new copy, Command/Ctrl+Z undoes, Command/Ctrl+Shift+Z redoes, Command/Ctrl+W closes a tab, Command/Ctrl+F shows Search and focuses its query, Command/Ctrl+K opens the command palette, Command/Ctrl+Q quits, and left/right arrows change pages when no widget has keyboard focus. File → Quit, the Quit palette action, the keyboard shortcut and the window close button share the same unsaved/busy-operation guard. The palette supports a filtered working-action list, Enter to execute the first enabled match, and Escape to dismiss.

On macOS, Winit's default native application menu is disabled because its Quit command directly terminates the process before the unsaved-change guard runs. The application's File → Quit action and logical Command+Q shortcut use the guarded route, verified with a real dirty document. Native Dock/system termination is a separate unverified path.

Twenty-four tests cover state/history, stale results, no-clobber saving, real-PDF search, case/Unicode matching, compact excerpts, actual query focus and typing, UTF-8 and result limits, completion/Stop state, real font-atlas glyphs, IBM Plex precedence and both theme/contrast settings. Actual light/dark and compact-window review, keyboard-focused search, scrollable inspector, palette actions and guarded quit are recorded in [runtime evidence](../../docs/NATIVE_DESKTOP_EVIDENCE.md). Accessibility activation/value assignment did not reliably focus or update the search input; Command+F followed by pasting worked. Exposed document text is not a complete screen-reader audit.

DPI tests exercise physical 2× rendering of a real synthetic PDF, unchanged logical display dimensions, DPI-stale result rejection, crop/rotation, nonfinite input rejection and exact ceiling-aware output limits. Retina sharpness was visually checked on macOS; multimonitor transitions and oversized-document limit messaging remain unverified at runtime.
