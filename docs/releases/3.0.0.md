## One-click private PDF workspace

PDF Editor Offline 3.0.0 is the first desktop release that does not require
Python, Node.js, Docker, or a terminal. The React workspace, authenticated
loopback API, Python runtime, and stable PDF engine are bundled together and
start as one application.

The shortest reason to upgrade is simple: load a PDF, remove sensitive text,
and get content-free evidence that the target is gone before sharing the saved
copy. The five primary workflows keep that outcome visible without hiding the
specialist tools that existing users rely on.

### Trust Workbench

- **Redact & Prove** finds every target, applies permanent redactions, reopens
  the exported copy, and distinguishes verified absence from unavailable checks.
- **Sanitize & Share** removes metadata, embedded files, scripts, links,
  annotations, and other selected private surfaces through explicit profiles.
- **Change Review and Safe Edit** compare visual, semantic, metadata,
  annotation, and structure evidence, then refuse a candidate that crosses the
  selected fidelity boundary.
- **Accessibility inspector** reports language, tags, reading order, headings,
  image alternatives, bookmarks, tables, and form-label evidence without
  claiming PDF/UA conformance it cannot prove.
- **Experimental Content Editing Lab** limits replacement to a documented
  Base-14 case, runs a preflight, requires acknowledgement, and rolls back
  atomically when post-edit checks fail.

### A task-first local workspace

Redact & Prove, Fill & Sign, Organize Pages, Sanitize & Share, and OCR & Search
are the five first-class workflows. `Ctrl/Command+K` searches every workflow and
specialist command. The startup trust panel shows loopback API health, the
per-launch token boundary, optional local engines, storage use, network policy,
and cleanup controls before a document is processed.

OCR stays local, uses only installed language packs, exposes confidence review,
and can remove its generated layer. Certificate signing and validation use
ephemeral request storage, explicit roots, and no automatic trust or certificate
network fetching. Visual signatures remain clearly separate from certificate
signatures.

### Evidence developers can reuse

Eight stable Draft 2020-12 schemas cover capabilities, redaction, privacy,
accessibility, change review, experimental content editing, the corpus, and
Trust Lab results. The CLI, FastAPI surface, Python package, and reusable GitHub
Action consume the same content-free contracts. PDF Trust Lab publishes nine
synthetic cases across PyMuPDF, pdfplumber, and PDFium with engine facts and
regression history rather than sample document content.

### What is verified

- Every artifact is built on its native clean GitHub runner.
- The frozen app completes `open → find every target → redact → export →
  reopen → verify absence` with a synthetic PDF.
- Install, launch, local API startup, application close, child-process cleanup,
  and uninstall/removal are exercised before upload.
- Windows is Authenticode signed and timestamped. macOS is Developer ID signed,
  notarized, and stapled.
- `SHA256SUMS`, a combined machine-readable manifest, CycloneDX SBOMs, and
  offline Sigstore provenance bundles are attached.
- A byte-reproducible synthetic sample pack includes the three safe PDFs, exact
  five-minute workflow, verification guide, and known limitations; it is covered
  by the same `SHA256SUMS` as every other public asset.
- GitHub-hosted provenance can be checked with `gh attestation verify`.

### Five-minute first workflow

Open the bundled desktop application, choose the synthetic redaction sample,
search for the marked secret text, review every match, apply redaction, run the
verification check, save a copy, and reopen that copy. A green result means the
target is absent from the checks the application actually performed; it never
means an unexecuted check was inferred as successful.

### Optional capabilities and limits

Opening, organizing, filling, redacting, sanitizing, and exporting PDFs work
with the bundled runtime. OCR language packs, LibreOffice conversions, and
Ghostscript-specific optimization remain optional local tools. The startup
health panel reports their availability before use and links to installation
guidance; the application never downloads them silently.

Linux compatibility is bounded by the Ubuntu 22.04 build baseline. Other glibc
distributions are best effort. Existing digital signatures can be invalidated
when document bytes are edited. Complex fonts, tagged-PDF structure, dynamic
forms, transparency, and malformed files can still produce fidelity warnings;
keep the original and review the exported copy.
