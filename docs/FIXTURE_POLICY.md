# Security fixture policy

The test corpus contains only synthetic documents generated by the test suite.
It must never contain customer, production, medical, legal, identity, or other
private material.

Adversarial fixtures cover malformed PDF syntax, suspicious compression
metadata, path-traversal filenames, oversized input, embedded JavaScript, and
unsafe-looking attachments. Fixtures are inert: scripts are stored as PDF
objects but never executed, attachments contain plain marker text, and tests run
without opening files in an external viewer.

Every fixture must have:

1. a deterministic generator or a reviewable text representation;
2. a stated threat and expected safe behavior;
3. a size small enough for source control and routine CI;
4. a regression test that rejects, sanitizes, or reports the condition;
5. no secrets, personal data, proprietary files, or active exploit payloads.

Large decompression and allocation cases are represented with small declared
limits or suspicious metadata rather than gigabytes of expanded data. Any
future real-world malicious sample belongs in access-controlled security
research storage, not this public repository.

The versioned public compatibility set, generation command, coverage table,
and visual/semantic comparison tolerance are documented in
[Synthetic compatibility corpus](TRUST_LAB_CORPUS.md).
