Download the CLI preview

The official prerelease contains five standalone native command-line executables. Choose your operating system and processor. These are unsigned technical preview binaries; the graphical desktop remains a source build.

  • macOS Intel (x64)pdf-editor-offline-darwin-x64
  • Windows x64pdf-editor-offline-windows-x64.exe

Official prerelease and notes · Binary sizes and SHA-256 manifest · Release verification evidence · Third-party notices

The five-platform CI run built and exercised these CLI executables. This does not establish graphical desktop runtime behavior on Windows or Linux.

Run the downloaded executable

For macOS Apple silicon, from the folder containing your download:

chmod +x ./pdf-editor-offline-darwin-arm64
./pdf-editor-offline-darwin-arm64 --help

On Intel macOS use pdf-editor-offline-darwin-x64. Linux uses the same executable-permission step with your downloaded Linux filename. For Windows x64, open PowerShell in the download folder:

.\pdf-editor-offline-windows-x64.exe --help

Use the chosen executable's name in place of ./target/release/pdf-editor-offline in the examples below. Run --version to check the installed preview version.

Optional npm install

The published npm package installs and launches the matching native CLI. Version 4.0.0-preview.3 is available through the default latest tag. The installer and launcher require Node.js 22 or newer; the standalone CLI downloads above run without Node.js.

npm install --global pdf-editor-offline
pdf-editor-offline --help

This installs the command-line tool. Build the graphical desktop from source using the next section.

Build the native preview

Use Rust 1.95 or newer and the platform development tools required by eframe and native file dialogs. Clone the repository, then run from its root:

git clone https://github.com/OthmaneBlial/pdf-editor-offline.git
cd pdf-editor-offline
cargo run --locked -p pdf-editor-offline-native

For a release build:

cargo build --release --locked -p pdf-editor-offline-native
./target/release/pdf-editor-offline-native

On Windows, the executable is target\release\pdf-editor-offline-native.exe. Platform build prerequisites and current checks are tracked in the desktop README and Rust status.

The macOS interface has been manually reviewed with real files and screenshots. Windows and Linux graphical runtime validation remain open. The desktop is available as source; standalone CLI prerelease downloads are available separately. The current desktop build still awaits a fresh GUI review, as recorded in the native evidence.

Working in the preview

Open a local PDF, use Pages or Search to navigate, and choose real actions from Edit, Organize or the command palette. Save As creates a new verified file. Modified tabs and unapplied document-property drafts guard quitting. Password entry is unavailable; protected inputs that need a password are refused.

Command/Ctrl+O opens, Command/Ctrl+F focuses Search, Command/Ctrl+K opens Commands, Command/Ctrl+Z undoes, and Command/Ctrl+Q uses guarded quit. File → Images to PDF creates a new unsaved document from supported PNG/JPEG inputs.

CLI quick start

Build once, then use the explicit executable path. Replace input.pdf and output names with your own paths; every output must be a new file.

cargo build --release --locked -p pdf-editor-offline-cli
./target/release/pdf-editor-offline info input.pdf --json
./target/release/pdf-editor-offline extract-text input.pdf
./target/release/pdf-editor-offline metadata input.pdf --json
./target/release/pdf-editor-offline inspect-security input.pdf --json
./target/release/pdf-editor-offline render-page input.pdf --page 1 --scale 1.5 -o page.png
./target/release/pdf-editor-offline rotate input.pdf --pages 1-3 --degrees 90 -o rotated.pdf
./target/release/pdf-editor-offline merge first.pdf second.pdf -o merged.pdf
./target/release/pdf-editor-offline images-to-pdf first.png second.jpg -o images.pdf --json

Page arguments are one-based. --dry-run is available on supported mutation commands to validate without publication. Signed and encrypted documents cannot be rewritten. Read the CLI command reference for reorder, crop, extraction, notes, metadata changes and output error codes.

Security inspection reports detected structures. It does not verify signature trust, sanitize the PDF or establish PDF/A or PDF/UA conformance.

Data and output boundaries

Rendering and document operations run locally. The native workflow does not require a web service or an account. Limits constrain inputs and output data; successful rendering alone does not establish document fidelity or safe handling of every hostile file.

  • PDF input: at most 128 MiB. Main preview output: 8192 pixels per side and 16,777,216 pixels total.
  • Thumbnails: visible rows only, a shared 8 MiB pixel-payload cache and at most 128 entries. Driver allocations and transient copies are additional.
  • Search: literal query, at most 200 matching pages; extracted page text retained up to 1 MiB. Partial results are reported.
  • Standard metadata fields: at most 64 KiB of UTF-8 each. Clearing a field removes its active entry; earlier data can remain in the file.
  • Image conversion: 32 MiB per encoded input, 128 MiB total before conversion, 8192 pixels per side and 8,388,608 pixels per image. One source pixel equals one PDF point.

PNG samples and alpha are preserved losslessly in the supported tier. JPEG codestreams are retained after bounded validation. Conversion is not a metadata sanitization operation, and different readers can sample transparency edges differently.

Read the converter boundaries, threat model and privacy notes before relying on a result.

Dated evidence, precise scope

The 13 October 2026 local release-CLI report at clean source ab0b24b passes 44/44 operation records, with zero failed or skipped records, in 7.973 seconds. It covers 11 fixtures, including a deterministic 1,000-page file, and four operation classes: info, text extraction, rotation and compression.

The earlier 12 October checkpoint at source 49bd559 recorded 229 normal workspace tests and 10 explicitly run reference/helper tests. Those 10 are additional tests, not a count of corpus documents. Later work changes the current test count; this is a dated checkpoint.

Pinned Poppler 26.10.0 and qpdf 12.4.2 validate defined geometry, text and structural boundaries. Reference work sits outside timed operation samples. The matrix does not measure native GUI responsiveness, peak process memory, comparative speedups, image conversion or complete raster fidelity.
