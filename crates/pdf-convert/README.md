# Native image-to-PDF conversion

`images_to_pdf(&[&image_bytes, ...])` returns a real, strictly reopened `PdfDocument`
and a per-page description. Inputs remain unchanged; no files are written. Publish
with `document.save_new(path)`, which verifies a new copy and refuses existing files.
Pages follow caller order. One source pixel occupies one PDF point; this is an
explicit sizing policy, not a claim to preserve printing density.

This initial tier accepts noninterlaced PNG: 8-bit RGB, RGBA, Gray and GrayAlpha,
plus 1/2/4/8-bit indexed or grayscale images expanded to 8-bit samples. Palette and
`tRNS` transparency become exact color samples and a separate straight-alpha PDF
soft mask. Compression is lossless, including colors under transparent pixels.
Untagged samples use DeviceRGB/DeviceGray. An explicit standard `sRGB` chunk becomes
a real shared ICCBased sRGB profile generated by the existing moxcms dependency;
the source rendering intent is preserved. Tagged gray samples are duplicated into
RGB without changing their values. Custom ICC, gamma/chromaticity, HDR, EXIF,
animation, interlacing, other ancillary metadata and greater-than-8-bit samples
are refused rather than discarded or guessed.

8-bit baseline/progressive Gray, RGB and YCbCr JPEG inputs are fully decoded with
strict bounds before their original DCT bytes are embedded unchanged. This adds
no JPEG recompression loss; the source JPEG may already be lossy. CMYK/YCCK,
nonstandard coding, EXIF (including orientation), XMP, ICC, MPF and other unsupported
APP metadata are refused. This does not yet implement photo orientation handling.
JFIF, supported Adobe transform markers and comments remain in the original DCT
data; conversion is not a metadata sanitization operation.

Limits are 8192 pixels per side, 8,388,608 pixels per image, 32 MiB per encoded
image and decoded sample stream, 1 MiB header/metadata per image, 64 JPEG scans,
20,000 pages and the core object limit. Encoded inputs, retained payloads and final
serialized PDF each have a 128 MiB aggregate cap. Header/chunk/marker preflight
runs before decoder allocation; the PNG decoder also has a 64 MiB internal budget.
These are data bounds, not an operating-system CPU or total resident-memory sandbox.
Conversion is transactional: an error returns no partial document.

Run `cargo test -p pdf-convert` for synthetic Rust fixtures proving page order,
geometry, exact samples/soft masks, sRGB profile/intent, JPEG preservation, upright
pixel orientation, unsupported metadata, corruption, dimension bombs and verified
save refusal. The independent gate requires Poppler 26.10.0 with JPEG support and
qpdf 12.4.2:

```sh
PDF_REFERENCE_BIN_DIR=/path/to/poppler/bin QPDF=/path/to/qpdf \
  cargo test -p pdf-convert --test images -- --ignored
```

It checks reader diagnostics, qpdf validity and independently decoded stream bytes,
page geometry and rendered source-pixel interiors. Full reader raster equivalence
is not claimed: adjacent partially transparent one-point pixels can sample
differently at density 1. The initial pinned Poppler reference rendered one green
half-alpha pixel as `[132,224,102]` where Hayro produced `[127,255,127]`, although
both PDF color and mask samples were exact. Density-8 interior checks avoid those
boundary samples without enlarging their color tolerance.
